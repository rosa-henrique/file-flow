## HTTP Proxy Configuration

### Proxy Setup
The development server uses `proxy.conf.js` to proxy HTTP requests:

```javascript
"/api" → resolves to the backend API service
```

**Environment Variables** (set by deployment/container):
- `services__api__https__0` - HTTPS backend URL (production)
- `services__api__http__0` - HTTP backend URL (development)
- `NODE_ENV` - Set to "development" for local dev (disables SSL verification)

**How it works**:
- Requests to `http://localhost:4200/api/*` are proxied to the backend
- Path rewriting removes `/api` prefix before forwarding
- In tests or non-dev environments, update the API base URL accordingly

## Best Practices for This Project

### Component Development
1. **Always use standalone components** for new components
2. Import only needed dependencies via `imports` array
3. Use SCSS for styling (global and component-scoped)
4. Implement `OnDestroy` if using subscriptions; use `takeUntilDestroyed()` helper

### Forms
- **@angular/forms** is available for both reactive and template-driven forms
- Use reactive forms for complex logic; template-driven for simple forms
- Material components can be used for form inputs

### HTTP Requests
1. Prefix API URLs with `/api` (proxy will handle routing)
2. Inject `HttpClient` from `@angular/common/http`
3. Example: `this.http.get('/api/endpoint')`
4. Use RxJS operators for request handling (map, catchError, takeUntilDestroyed, etc.)

### Signals & Reactivity
- Use `signal()` for local component state
- Use `computed()` for derived state
- Use `effect()` carefully (avoid side effects in effects)
- Combine with async pipe in templates for automatic subscriptions

### Testing
- Test files use `.spec.ts` extension
- Framework: Vitest
- Run: `npm test`
- Use component testing patterns with TestBed (standard Angular testing)

### Code Style
- **Formatter**: Prettier (run via `prettier --write .` if needed)
- **Naming**: camelCase for variables/methods, PascalCase for classes/components
- **File naming**: kebab-case for files (e.g., `create-upload-batch.ts`)

### Spacing Scale
Follow this consistent spacing scale across all components:
- `0.25rem` - Minimal gaps
- `0.5rem` - Tight spacing
- `0.75rem` - Button/control spacing
- `1rem` - Standard padding
- `1.5rem` - Large padding (containers, sections)
- `2rem` - Section spacing
- `2.5rem` - Major section padding
- `3rem` - Large content spacing

### Responsive Design
- Use `clamp()` for responsive font sizes: `font-size: clamp(1.75rem, 2.2vw, 2.5rem)`
- Mobile-first approach with media queries when needed
- Use flexbox/grid for layouts (avoid floats)
- Test at: 375px (mobile), 768px (tablet), 1200px (desktop)

### Material Design Integration
- Import Material components via `@angular/material`
- Use Material's built-in styling when possible
- Override Material theme colors in global `styles.scss`
- Material buttons and form controls inherit dark theme automatically

### Do's & Don'ts

**✅ DO:**
- Use SCSS variables and nesting
- Follow BEM naming: `.block__element--modifier`
- Use CSS custom properties from Material theme
- Apply consistent spacing from the scale above
- Style form inputs with error states (`.is-invalid`, `.error-message`)
- Use transitions for interactive elements (e.g., `transition: border-color 0.3s ease`)

**❌ DON'T:**
- Use inline styles in templates (`[style]=` or `style=""`)
- Create custom color variables outside Material theme
- Mix light and dark theme colors
- Use px units for spacing (use rem instead)
- Add !important unless absolutely necessary
- Create inconsistent border-radius values (use 4px, 8px, 1.5rem)

---Aspire Integration

### What is Aspire?
This frontend is part of a **Microsoft Aspire** orchestrated application. Aspire handles:
- Service discovery and networking
- Container orchestration (local development)
- Environment variable injection
- Health monitoring and logging aggregation

### Frontend Role in Aspire
- **Frontend Service**: Runs as a containerized Angular app
- **Backend Service**: Handles all business logic, validation, and persistence
- **Communication**: Via HTTP through the proxy (REST API at `/api`)

### Local Aspire Development
When running via Aspire orchestration:
- Services are auto-discovered and networked
- Backend URL is injected via `services__api__http__0` or `services__api__https__0`
- Frontend automatically proxies to backend via `proxy.conf.js`
- No manual service URL configuration needed

### Important: Backend Handles Abstraction
The frontend **delegates** the following to the backend:
- ❌ File storage (object storage/blob storage abstraction)
- ❌ Database persistence
- ❌ AFrontend is UI layer only** - This is a thin UI client. Business logic, validation, and persistence are in the backend. Don't implement business rules in components; call backend APIs instead.
